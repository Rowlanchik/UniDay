# UniDay для iPhone

Это самостоятельный iOS-проект с WKWebView и одним расширением WidgetKit для Small, Medium и Large. Scriptable для работы приложения не нужен. Все функции исходного UniDay 7.9.0 сохранены в `App/Resources/legacy.js`; адаптеры заменяют API Scriptable нативными API iOS. Реестр функций и результаты проверок: [FEATURE-PARITY](docs/FEATURE-PARITY.ru.md).

**Первый перенос пока требует испытаний на двух iPhone.** Успешная сборка не доказывает работу App Groups после бесплатной переподписи и не подтверждает отсутствие отличий во всех экранах. Точный порядок: сначала минимальный IPA → проверка двух Apple Accounts → проверка полного UniDay → выпуск стабильной версии. [Проверка устройств](docs/DEVICE-TESTS.ru.md).

## Постоянный источник

`https://rowlanchik.github.io/UniDay/source.json`

Друг один раз устанавливает AltStore Classic, добавляет этот источник и устанавливает UniDay. Следующие версии появляются в том же источнике. Для установки новой версии нужно нажать **Update / Обновить**. **Refresh All** лишь продлевает подпись установленной версии. UniDay проверяет источник при открытии, показывает текущую и доступную версии, изменения и открывает страницу приложения в AltStore Classic.

IPA постоянно хранятся в [GitHub Releases](https://github.com/Rowlanchik/UniDay/releases). Ссылки Actions artifacts используются только для отладки, срок их хранения ограничен. Источник содержит новые и предыдущие версии; предыдущие Releases не удаляются.

## Установка на Windows и iPhone

Короткая инструкция для друга: [FRIEND](docs/FRIEND.ru.md). Короткая инструкция для выпуска: [OWNER](docs/OWNER.ru.md).

Основной путь: AltStore Classic 2.3 или новее + AltServer Windows. Нужны официальные iTunes и iCloud от Apple, USB для первоначального сопряжения, доверие компьютеру, собственный Apple Account каждого пользователя. При бесплатной подписи приложения действуют 7 дней; ограничения Apple на активные приложения и App IDs остаются. UniDay использует два App IDs: приложение и один WidgetKit extension. При вопросе об удалении расширений выбирайте **Keep App Extensions**; без этого виджета не будет. AltStore PAL — другой продукт.

На базовом пути для Refresh нужен доступный AltServer по USB или в той же Wi-Fi сети. В Classic 2.3 появился дополнительный Remote AltServer: после настройки LocalDevVPN и сопряжения можно уменьшить зависимость от своего Windows-компьютера. Он имеет дополнительные условия и зависит от доступности сервиса. SideStore сравнен по текущим официальным источникам; обнаруженное предупреждение о сломанном входе в старых стабильных версиях не позволяет рекомендовать их как основной путь. Подробности и ссылки: [проверка распространения](docs/DISTRIBUTION-RESEARCH.ru.md).

## Данные и обновления

Каждый вводит собственную календарную ссылку, остановки, места и оформление. Личный профиль в исходники и IPA не включён. Apple Account и пароль вводятся пользователем только в установщике; GitHub Actions не получает их.

Профиль, заметки, правки занятий, вещи, отметки, личные события, кэш и изображения находятся в контейнере UniDay. Обновление устанавливается поверх приложения с тем же исходным bundle identifier и тем же аккаунтом подписи. Не удаляйте приложение перед обновлением и не переключайте подписывающий Apple Account у уже используемой установки без резервной копии.

Меню → **Экспорт полной резервной копии** сохраняет JSON через меню «Поделиться». Меню → **Восстановить резервную копию** проверяет формат и сохраняет локальную копию старых данных перед заменой. Неподдерживаемый новый формат и повреждённые данные не сбрасываются в пустой профиль. Дополнительные поля сохраняются при миграции `v0 → v1`, а исходные миграции профиля 7.9.0 продолжают работать.

Для однократного переноса из Scriptable запустите [Export-UniDay-Backup.js](scripts/Export-UniDay-Backup.js) внутри Scriptable на своём iPhone. Он экспортирует профиль вместе с заметками, вещами, отметками и фонами. Затем восстановите этот JSON в новом UniDay. Обычный экспорт профиля 7.9.0 переносит настройки, но не все отдельные файлы заметок и списков. Резервные копии содержат личные данные: храните их у себя, не добавляйте в GitHub.

## Приложение и виджет

Основной обмен: общий контейнер App Groups, разрешённый фактической подписью. AltStore может изменить group identifier под Apple Account. UniDay определяет его из установленного исполняемого файла/профиля и проверяет получение своего контейнера. Диагностика показывает идентификаторы и результат. При недоступной группе приложение сохраняет данные в собственном контейнере; виджет сообщает об отсутствии настроек. Есть резервный режим: локальный экспорт настройки для вставки в конфигурацию виджета, с отдельным профилем и без автоматической синхронизации последующих правок приложения.

Виджет выполняет те же движки календаря, транспорта, погоды и компоновки через JavaScriptCore. Данные получает по HTTPS сам; кэш виджета отделён от пользовательской базы приложения. Возраст данных отображается. Геопозиция использует последнюю точку приложения с проверкой свежести. iOS управляет сроком обновления WidgetKit; запрос на обновление не гарантирует каждые 30 секунд или ровно каждые 5 минут. Системный таймер продолжает отсчёт без новых сетевых запросов. Нажатие открывает `uniday://overview`, остановки открывают соответствующее табло.

## Облачная сборка

Стандартный `macos-15` runner публичного GitHub-репозитория бесплатен по официальным правилам GitHub; larger runners не используются. Версия Xcode записывается в журнал сборки. XcodeGen генерирует проект из `project.yml`. Сборка устройства выполняется без Apple-подписи. Для сохранения запроса App Groups перед упаковкой добавляется локальная ad-hoc подпись без сертификата Apple; она не позволяет непосредственно установить IPA на iPhone. Окончательную бесплатную подпись выполняет AltStore на аккаунте каждого пользователя.

Workflow `Build and publish UniDay`:

1. Запускает проверки JavaScript и упаковки/источника.
2. Собирает приложение вместе с `PlugIns/UniDayWidget.appex`.
3. Проверяет entitlements, упаковывает `Payload/UniDay.app` и SHA-256.
4. Для smoke создаёт тестовый GitHub Release; для release публикует IPA и обновляет `gh-pages/source.json` реальными версией, датой, размером, ссылкой и объединёнными разрешениями приложения и расширения.
5. Сохраняет старые версии в источнике и все старые IPA в Releases.

В Settings → Pages выберите источник **GitHub Actions**. Workflow сохраняет историю source.json в ветке **gh-pages** и развёртывает сам сайт через Pages Actions. Сайт нужен только для JSON и инструкции, приложение работает локально.

## Проверки и пределы подтверждения

Локально доступны проверки исходных движков, адаптеров, формата данных и упаковки. Компиляция Swift подтверждается только успешным GitHub Actions. Установка, реальная переподпись, появление виджета, доступ к общей группе, глубокие ссылки и сохранение данных при обновлении подтверждаются отдельными испытаниями на каждом iPhone. Не переносите результат одного телефона на другой.
