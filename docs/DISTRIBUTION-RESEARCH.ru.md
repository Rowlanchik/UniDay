# Бесплатное распространение UniDay: проверка на 7 октября 2026

Основной путь — **AltStore Classic**, установленный через **AltServer на Windows**, и один публичный источник: [UniDay source.json](https://rowlanchik.github.io/UniDay/source.json). Каждый телефон переподписывает один и тот же IPA своим Apple Account. Календарь и профиль каждый пользователь вводит локально. Публикация одного выпуска делает его доступным обоим телефонам; установка новой версии требует действия пользователя.

## Источники в бесплатном AltStore Classic

В стабильном AltStore Classic 2.0 появились произвольные сторонние источники. Patreon нужен для отдельных платных приложений или бета-сборок, а не для нашего бесплатного источника. Classic 2.2 добавил отдельную схему `altstore-classic://`. На дату проверки стабильный Classic 2.3 поддерживает iOS 17.4 и новее. Для более старой iOS следует проверить последнюю совместимую стабильную версию; источники доступны начиная с 2.0. **AltStore PAL — другой способ распространения, для этого IPA не используется.** [Официальные заметки Classic](https://faq.altstore.io/release-notes/altstore), [стабильный v2.3](https://github.com/altstoreio/AltStore/releases/tag/v2.3).

В `source.json` список `versions` упорядочивается от нового к старому. AltStore сравнивает первый совместимый выпуск с установленным, а не сортирует даты. После обновления источника он обнаруживает версию и уведомляет пользователя. Нажатие **Update / Обновить** устанавливает новый IPA. **Refresh / Продлить** обновляет подпись уже установленной версии: это отдельная операция. [Официальное руководство обновлений](https://faq.altstore.io/developers/updating-apps).

Каждый выпуск должен содержать `version`, `buildVersion`, дату ISO 8601, описание изменений, постоянную ссылку GitHub Releases, фактический размер IPA в байтах, минимальную iOS и SHA-256. Версия и номер сборки должны точно совпадать с `Info.plist`. `appPermissions` перечисляет объединение entitlements приложения и всех расширений, а `privacy` — фактические UsageDescription из их Info.plist. AltStore проверяет соответствие IPA. Разрешения обязательных идентификаторов команды и приложения отдельно перечислять не требуется. Предыдущие стабильные записи и файлы Releases сохраняются. Ссылки Actions artifacts для установки не используются. [Формат источника](https://faq.altstore.io/developers/make-a-source).

Кнопка UniDay открывает `altstore-classic://viewApp?bundleID=io.github.rowlanchik09.UniDay`: это страница приложения в добавленном источнике, где пользователь нажимает обновление. Для первоначального добавления предусмотрено `altstore-classic://source?url=` с закодированной ссылкой источника. Исходный bundle ID здесь берётся из source JSON, не из переподписанного приложения. Обработчик `viewapp` ищет приложение в базе источников. Эти переходы подтверждены кодом, их фактическое открытие на обоих телефонах ещё требуется проверить. [Обработчик ссылок v2.3](https://github.com/altstoreio/AltStore/blob/v2.3/AltStore/SceneDelegate.swift), [зарегистрированные схемы](https://github.com/altstoreio/AltStore/blob/v2.3/AltStore/Info.plist).

## Windows и сокращение зависимости от компьютера

Первичная установка: iTunes и iCloud из прямых загрузок Apple, AltServer с официального сайта, USB-подключение, доверие компьютеру, включение синхронизации Wi-Fi в iTunes и установка AltStore с **собственным** Apple Account. Для iOS 16+ включается Developer Mode. [Официальная инструкция Windows](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows).

В обычном режиме для установки, обновления и продления подписи нужен запущенный AltServer: телефон подключён USB или находится в одной Wi-Fi сети с Windows. Фоновое продление — попытка, не гарантия. Если AltStore истёк, его переустанавливают через AltServer поверх существующего приложения. [Официальное описание AltServer](https://faq.altstore.io/altstore-classic/altserver), [описание Refresh](https://faq.altstore.io/altstore-classic/your-altstore).

**Актуальное улучшение:** в Classic 2.3 появился Remote AltServer. После первого сопряжения с компьютером в Settings → Set up Remote AltServer можно устанавливать и продлевать приложения без постоянно включённого своего Windows. Нужны Wi-Fi, включённый LocalDevVPN и доступный удалённый сервер. При недоступности можно выбрать другой сервер; обычный AltServer остаётся запасным путём. Это уменьшает число действий, но не отменяет сроки Apple и не устанавливает новые версии UniDay без нажатия. [Официальная настройка Remote AltServers](https://faq.altstore.io/altstore-classic/remote-altservers).

## Почему IPA содержит ad-hoc метаданные

Облачная сборка отключает подпись Apple: `CODE_SIGNING_ALLOWED=NO`, без Apple Account, сертификата и provisioning profile. Однако для запроса App Groups при переподписании в Mach-O необходимо сохранить entitlements. AltSign извлекает их через `ldid::Entitlements`; отдельного исходного `.entitlements` рядом с приложением недостаточно. Без них он видит пустой набор возможностей. [Официальный ALTApplication.mm](https://github.com/rileytestut/AltSign/blob/master/AltSign/Model/ALTApplication.mm).

Поэтому перед упаковкой macOS добавляет локальную ad-hoc подпись `codesign --sign - --entitlements ...` сначала расширению, затем приложению. Это **IPA без подписи Apple**, а не готовый устанавливаемый пакет с выданными разрешениями. Эта локальная подпись лишь переносит запрос возможностей; AltStore заменяет её личной подписью и профилями пользователя. В CI entitlements повторно извлекаются из обоих готовых бинарников и сверяются с ожидаемым набором и источником.

## Два Apple Accounts и общий контейнер

В Classic v2.3 есть путь регистрации App Groups без отдельной проверки платного типа команды. Для обычного приложения первоначально применяются правила:

| До переподписания | Ожидаемая форма после AltStore |
| --- | --- |
| `io.github.rowlanchik09.UniDay` | `io.github.rowlanchik09.UniDay.TEAM` |
| `io.github.rowlanchik09.UniDay.Widget` | `io.github.rowlanchik09.UniDay.TEAM.Widget` |
| исходный `group.…` UniDay | `group.….TEAM` |

При повторной установке с той же командой AltStore предпочитает уже использованный bundle ID. При другой команде создаёт другую идентичность. Это важное условие сохранения контейнера при обновлении: **на каждом телефоне нужен прежний Apple Account и прежний установщик**. Таблица отражает код, не результат установки. [FetchProvisioningProfilesOperation v2.3](https://github.com/altstoreio/AltStore/blob/v2.3/AltStore/Operations/FetchProvisioningProfilesOperation.swift).

AltStore записывает группы из профиля в `ALTAppGroups` **и для приложения, и для расширения**; сохраняет исходный bundle ID как `ALTBundleIdentifier`. UniDay должен находить только собственную фактически разрешённую группу, проверять получение контейнера и показывать диагностику при отказе. Жёстко записанная исходная группа после переименования ненадёжна. Чужие контейнеры или группа самого установщика не используются. [ResignAppOperation v2.3](https://github.com/altstoreio/AltStore/blob/v2.3/AltStore/Operations/ResignAppOperation.swift).

Наличие записи в проекте, Info.plist или даже профиле само по себе не подтверждает работоспособность обмена на iPhone. Подтверждение — чтение записанного приложением тестового значения в отдельно запущенном WidgetKit extension, с одинаковой группой и подходящими профилями. Приложение и виджет на телефоне A используют группу команды A, на телефоне B — группы команды B. Устройства не должны обмениваться профилями.

Для доступа используется только публичный `FileManager.containerURL(forSecurityApplicationGroupIdentifier:)`: на iOS он возвращает `nil` для недействительной группы. Пути к контейнеру вручную не конструируются. После получения URL выполняется реальная пробная запись/чтение; приложение при отказе сохраняет собственные данные в своей песочнице, а виджет показывает ошибку обмена. [Контракт API Apple](https://developer.apple.com/documentation/foundation/filemanager/containerurl(forsecurityapplicationgroupidentifier:)).

Если Apple откажет в этой возможности для конкретного бесплатного аккаунта, основной сценарий обмена считается не прошедшим. Допустимая отдельная архитектура — виджет со своей конфигурацией и собственными сетевыми запросами/кешем. Она требует повторного ввода календаря/остановок для виджета и не обеспечивает синхронизацию локальных заметок и списков с приложением. Поэтому это не равноценная замена всех функций UniDay и не основание отмечать перенос завершённым.

## SideStore по актуальным официальным источникам

SideStore также поддерживает источники и обычные IPA. Его документация описывает первичную установку через iloader на Windows, затем LocalDevVPN и Wi-Fi на телефоне. Для установки/обновления/Refresh VPN должен быть включён. [Требования SideStore](https://docs.sidestore.io/docs/installation/prerequisites), [установка](https://docs.sidestore.io/docs/installation/install).

У SideStore есть поддержка расширений и собственных виджетов: релиз 0.6.3 содержит исправление виджета. Вариант **Remove Extensions** удаляет WidgetKit extension. Для UniDay требуется сохранять расширение и регистрировать ему собственный профиль; экономию App IDs через профиль основного приложения нельзя считать проверенной совместимостью WidgetKit. [Релиз 0.6.3](https://github.com/SideStore/SideStore/releases/tag/0.6.3), [заметки об extension profiles](https://docs.sidestore.io/docs/release-notes).

**Причина оставить SideStore альтернативой:** на дату проверки официальный релиз 0.6.4 помечен **DO NOT USE** и предупреждает, что вход сломан в 0.6.4 и более ранних версиях. В списке также есть alpha/nightly. Их нельзя выдавать за стабильную проверенную установку. Документация отстаёт от GitHub Releases. Перед реальным переходом нужно снова проверить предупреждения и протестировать выбранную сборку на двух аккаунтах. [Официальное предупреждение 0.6.4](https://github.com/SideStore/SideStore/releases/tag/0.6.4).

SideStore уменьшает зависимость от компьютера в обычной работе, но компьютер снова может понадобиться: pairing file иногда истекает после обновления/сброса iOS или по другим причинам. Теперь похожий путь есть и у стабильного AltStore Classic 2.3. Обнаружение версии, ручная установка новой версии и продление подписи остаются разными действиями. [SideStore: pairing и установка](https://docs.sidestore.io/docs/installation/install), [SideStore FAQ: OTA update](https://docs.sidestore.io/docs/faq).

## Ограничения, которые остаются бесплатными

Apple подтверждает для Personal Team: до 10 App IDs, до 3 устройств, до 3 приложений на устройство и профили на 7 дней. Один widget extension требует отдельный App ID; все размеры должны находиться в одном расширении. Сам AltStore тоже занимает место в ограничении приложений. [Ограничения Apple](https://developer.apple.com/help/account/basics/about-your-developer-account), [App IDs в AltStore](https://faq.altstore.io/altstore-classic/app-ids).

WidgetKit определяет время перезагрузки и бюджет. Запрос `reloadTimelines` не является обещанием мгновенного изменения. Виджет не работает постоянно; для часто видимого виджета Apple приводит типичный бюджет 40–70 обновлений в сутки. Поэтому UniDay показывает возраст сетевых данных, кеш и системный таймер, не обещает автобусные запросы каждые 30 секунд или ровно каждые 5 минут. [Apple: Keeping a widget up to date](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date).

## Что нужно подтвердить отдельно на каждом телефоне

Здесь подтверждены документация, устройство протокола источников и исходный код установщиков. **Установка UniDay, выдача групп Apple, фактические подписи, работа виджета и сохранение данных на телефонах пока не проверены.** Даже успешная облачная сборка не закрывает эти проверки.

| Проверка | Телефон A / Account A | Телефон B / Account B |
| --- | --- | --- |
| Установка из одного постоянного источника | ожидает теста | ожидает теста |
| Приложение запускается, виджет виден в галерее | ожидает теста | ожидает теста |
| Фактические bundle IDs и профиль приложения/extension | ожидает теста | ожидает теста |
| Собственная группа разрешена обоим процессам | ожидает теста | ожидает теста |
| Новое тестовое значение отображается виджетом | ожидает теста | ожидает теста |
| Нажатие карточки открывает `uniday://overview` | ожидает теста | ожидает теста |
| Все размеры виджета и переход к остановке | ожидает теста | ожидает теста |
| Продление подписи без потери данных | ожидает теста | ожидает теста |
| Обновление N → N+1 из источника | ожидает теста | ожидает теста |
| Календарь, остановки, настройки, заметки, вещи сохранены | ожидает теста | ожидает теста |
| Миграция старого формата и экспорт/импорт резервной копии | ожидает теста | ожидает теста |

Пароли, календарные ссылки, резервные копии профиля, pairing files и приватные ключи остаются локальными. При сообщении результата достаточно отметок таблицы и обезличенной диагностики, без содержимого календаря и файлов подписи.
