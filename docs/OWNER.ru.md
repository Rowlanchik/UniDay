# Для владельца: выпустить обновление

Первый полный выпуск отмечайте тестовым, пока приложение и виджет не проверены на двух телефонах по DEVICE-TESTS.ru.md.

Через сайт GitHub: откройте Actions → **Build and publish UniDay** → **Run workflow**. Для первого теста выберите `smoke`. Для полного приложения — `release`, укажите новую версию `8.0.1`; оставьте `prerelease` для тестового переноса. Для обычного стабильного выпуска снимите `prerelease`.

После изменения исходников и описания в CHANGELOG.md можно выпустить одной командой из корня клонированного проекта:

```powershell
.\scripts\release.ps1 8.0.1
```

Команда проверяет чистую рабочую папку, создаёт тег `v8.0.1` и отправляет его в GitHub. Если исходники ещё не сохранены, сначала сохраните и отправьте изменения обычным способом. Тег запускает бесплатную macOS-сборку приложения с виджетом. IPA появляется в Releases, source.json обновляется автоматически, предыдущие версии остаются доступны.

Проверьте зелёный результат Actions и новую запись по постоянному адресу `https://rowlanchik.github.io/UniDay/source.json`. Оба пользователя увидят версию через источник и нажмут «Обновить». Не нужно отправлять IPA другу. Продление подписи выполняется отдельно в AltStore.

Не меняйте постоянные bundle identifiers, исходный App Group и адрес источника между версиями. Не удаляйте прежние Releases. Не публикуйте календарную ссылку, профиль или резервные копии. Если сборка/публикация не прошла, версия не считается выпущенной; журнал Actions покажет причину.
